# Feta — project guide for Claude Code

Feta is a personal AI lifestyle companion that learns a person's taste and decides for them: places to eat and drink, things to do, style, and trips. **Personalised curation is the product** (founder, 15 Nov 2026): what people tell Feta must decide what it finds.

This page holds the **current rules only**. The reasons and history behind them are in `docs/decisions.md` (add new decisions there, dated). If the two disagree, this page wins. Designs: `design/README.md`, `design/DATA_CONTRACT.md`, `design/prototype/Feta App v2.dc.html`; the design wins for look, this page for data, privacy and behaviour. Redesign mock (14 Nov 2026): https://claude.ai/artifact/StSCbvNLSQ4uz5LYjHiw4v

## Working with the founder
- Srilakshmi is non-technical. Explain in plain English, one short paragraph at a time. Think about the whole flow and the root cause before building; mock up UX changes first.
- **No stacking.** If a fix needs a special case on top of other logic, the base is wrong: change the base and delete what it replaces.
- **One change per commit.** She tests the whole set together on https://askfeta.com (auto-deploys from main; feta-beige.vercel.app still works), so push when the set is done and tested.
- **Quality check first.** Every change to picks must pass `npm run eval` (realistic profiles against made-up places, ₹0). Add a profile when a tester finds a new kind of miss. A live run (`EVAL_LIVE=1`, about ₹50) only with her OK.
- Ask before adding a paid service, creating accounts, deleting anything, or spending money on tests. Never put keys or secrets in code or commits (`.env.local`, listed in `.env.example`). Migrations go on her clipboard for the Supabase SQL Editor; after adding one, run `npm run schema` (the eval fails until you do), so Admin's database check (`components/AdminHealth.tsx`, `schema_objects()`) names any migration that never ran.
- Suggest automations (n8n, Vercel, Claude scheduled tasks) in a line or two when a step could be automated; don't set them up without her go-ahead.

## Stack
Next.js 16 (App Router; `useParams`/`useSearchParams` need `<Suspense>`), Supabase (auth, RLS, Postgres), Vercel. Google Places API (New) for places; Gemini 3.5 Flash ranks places and reads taste; Venice (`claude-haiku-5-5`, `lib/server/venice.ts`) runs the chat. **Venice never receives Google content**; Gemini gets only Feta's own data plus live place descriptions.

## Flow
Welcome (3 cards, 18+ on the last) → `/start` (first name, required; "What do you want from Feta?": Places to eat and drink, Things to do, What to wear, Plan a trip) → `/location?setup=1` (their location or a city, then area / anywhere; before the questions since 19 Nov 2026, so they show that city's money and cuisines) → `/questions` (at most 4 screens, only for what they chose: basics; places they love, no limit, then "Recommend them to people like you?"; cuisines (all 12 tiles, Indian and world in turn; up to 4 + Something else, where a cuisine Feta has a tile for counts as chosen and other words stay as "Also loves …") and things to do (+ own words); one vibe card) → Home. A trip alone asks no category questions; a category they didn't choose asks its questions the first time it's opened (`components/FirstTime.tsx`). Sign-in (Google) is offered once on Home after the first picks.

Home: date · area, ★ Feta Picks and You buttons, "Hi <name>!", Choose for me (mood: new / usual / surprise; `components/ChooseForMe.tsx`), the wanted category as the big tile, the other smaller, Plan my evening, Style, Plan a trip. Tabs: Picks + Style, Saved (Want to try, Been, Plans), Ask (🧀); You from the round button. "How was it?" is a pop-up (after a plan: "How was Saturday?" for every stop); from the second visit, a card asks testers to fill in the Google Form (`components/TesterForm.tsx`, https://forms.gle/bfadwNw1mVzT3uLj8; Later brings it back every visit until they open it; never a lock, never on top of another pop-up, after "Save your taste" has had its turn).

## How picks work
One path for every caller (Picks, Home, Ask Feta, Plan my evening, trips; Plan my evening's nearby search too since 18 Nov 2026), in `lib/server/`:
1. **What they want** (`intents.ts`): every choice becomes an intent: what they asked for right now (chat note, tweaks), then everything they've shared **taken in turn** (a favourite cuisine or interest, their own words, what their loved places have in common (`taste-reader.ts`, Gemini, kept in memory an hour), then the next of each), so no kind crowds out another; taste-card sides last. The more they share, the more each set reflects it. Search words and which Google types count as a match live **only** in `catalog.ts`; the eval fails if a choice on screen has no entry.
2. **Find** (`curate.ts`): one Google text search per intent, up to 4 per set (`MAX_SEARCHES`), plus what's popular nearby when there's room (places to eat and drink, or things to do: attractions, galleries, theatres, parks, bowling). If more were chosen, they take turns across sets: never searched first (a choice just added in You comes in the very next set), then the ones searched longest ago (`pick_sets.searched`, the last day's sets). Their distance is a hard limit, never stretched (founder, 19 Nov 2026); too few within it means a shorter list that says so. **Things to do use exactly the same steps as food** (founder, 17 Nov 2026): what they shared, their loved places, popular nearby, the new-or-usual lean, Feta Favourites.
3. **Hard filters in code** (`picks.ts` `applyHardFilters`): diet, budget, distance, drinks, opening hours, closed, already saved/skipped/been, and quality (`poorlyKnown`: rated below 3.8 by 20+ people, or fewer than 5 reviews). Never left to the AI.
4. **Rank**: Gemini orders the places for this person and says which intents each "serves" (it can confirm, never add, a match). Test mode uses `fakeRank`.
5. **Keep the promise** (`selectPicks`): each thing they chose gets its best place among the 8 when one passed (even if very popular); then every Feta favourite the ranking thinks fits, best fit first, with no set number per source (founder, 19 Nov 2026: "think about what fits them the best… keep Google search the last"); places for their choices fill at least half; then the ranking. **No filler** (founder, 19 Nov 2026: "the whole point of this app is showing customised suggestions"): once they've shared anything, every place shown or kept as backup is for something they chose, said or love, or a curated place that fits; what's merely popular nearby never fills a set, and a short list says so ("Only 3 places really fit you here tonight. No weak filler."). One branch per chain, at most 1–3 very popular places (novelty), a few of one kind at most. Shown in this order: her places, loved by Feta users, local favourites, Featured in, then Google's, best fit first within each (founder, 19 Nov 2026). Anything chosen that found nothing is said plainly in the banner ("No Korean near you that fits tonight").

A request can narrow itself, in the engine and nowhere else (founder, 18 Nov 2026: one path for every screen): `only: "asked"` keeps just the places that match its note (Ask Feta, Plan my evening's after-dinner search; no everyday filler, no events); `at` checks a day and time; `reach` changes the distance for that one ask (`walk` near a dinner, `day_trip` up to 80 km); `searches` caps Google searches. Screens never re-filter or re-rank results themselves.

**Things to do are led by what's on** (founder, 19 Nov 2026: "lets not only focus on places, lets focus on events and things to do"): for each thing they chose, said or love (comedy, karaoke, pottery, hiking…), one Google Search grounding call finds events of that kind tonight or this weekend in the city (`findEvents` with a kind; about ₹3, shared by everyone there into the same thing through `events_cache`, 3 h / 12 h), with no set number of searches or events. Events that pass the hard filters (date, budget, distance via the venue) come first, taking turns across what they're into, each serving the thing it was found for; places fill the rest. The first search of the day waits up to 15 s for them, then keeps filling the cache after replying.

Then `engine.ts` adds verdicts, reasons ("Because you love Thai & SE Asian food" when Gemini's doesn't fit), stores the set (place IDs and Feta's words only) and builds cards. Sets are reused for 3 h (tonight) / 12 h (weekend), keyed by place **and a taste fingerprint**, so any change in taste searches again; the phone also drops its kept picks (`forgetPicks`).

Rules inside the filters:
- **Vegetarian, veg + eggs, Jain, vegan**: Google's "serves vegetarian food" must be yes; **in India a place with no answer also passes**, with the chip "Veg options · not confirmed, check with staff"; abroad it doesn't. Places mainly about meat or fish never pass (type, name, and Gemini's flag). Never "pure veg"; never say food is safe for a diet.
- **Pescatarian**: places mainly about meat are dropped. **No beef / no pork**: places mainly about it are dropped. Halal can't be checked: a "not confirmed" chip only.
- **No alcohol**: places whose main type is a bar, pub, club or brewery are dropped (a restaurant with a bar is fine).
- **Things to do** never show a bar (founder, 19 Nov 2026: bars belong in Food & drinks; karaoke and live music nights there come as events), nor a café or restaurant unless it matched something they're into that happens there (board games, comedy, live music). Hidden bars and rooftops are searched in Food & drinks (`drinkPlace` in `catalog.ts`).
- Spend is a range: the levels they ticked (`spendRange` in `lib/onboarding.ts`; the top is the most they'll spend and a place clearly above it is dropped; the bottom is never a filter (founder, 19 Nov 2026: a great cheaper place still fits); "Depends on the day" stands alone and means no limit). Levels travel between currencies (`lib/currency.ts`); a place or event with no price passes. Cheaper and Fancier move the range a level. Tonight: open now after 5 pm, else open an hour between 7 and 10 pm today (city time). Weekend: Sat or Sun hours.
- Verdicts: "Good if you're nearby" by default, "Worth a detour" at most once per set, "Skip unless…" for a real, checkable compromise. Chips are written by code from facts.
- Small cities (< 300k) also take only places the ranking chose. Someone who hasn't shared anything yet gets what's popular nearby.

**Feta Favourites**: the founder's places (`founder_places`, FETA PICK with her note: her own list, plus any place she marks Loved it in the app, kept in step by `syncFounderLoved` whenever she rates one) and places Feta users loved and chose to recommend (`pick_actions.recommend`; `feta_favourites()` puts people with a shared cuisine or interest first; `feta_love_counts()`). Ones found by the search cost nothing; up to 4 founder places within their distance (the ones whose name and note match most of what they want, then the nearest) and 2 community places are checked live per new search. Where her places are is kept for up to 30 days, as Google allows (`founder_places.lat/lng/located_at`, looked up when missing or older than 25 days, about ₹0.4 each; forgotten nightly after 30 days; `lib/server/feta-places.ts`). The founder's places may come back even if the person has been or saved them; only a skip hides one. The ★ button next to You on Home (`components/FetaStar.tsx`; every time Home shows, when the city has her places, the pill at the top says "★ Feta Picks in <city>" and the star flies into the button) opens polaroids, her note handwritten (`/api/feta-picks`, `components/FetaPicksSheet.tsx`), of her places and favourites from people with a similar taste that fit their diet, budget and distance, nearest first (up to 10 checked live when opened, about ₹20, kept on the phone an hour; closed places say "Closed now"). Cards show "♥ Loved by N Feta users"; never who.

**Local favourites** (founder, 19 Nov 2026): about 2,700 places locals recommend in 187 cities, from her research (an Excel built from Reddit threads and page reads), kept in `founder_places` with `source = 'local'`: place ID, name, kind, city only; no note, nothing quoted from Reddit or Zomato, no hours or prices (Google's live data decides). Up to 3 per new search are checked live (what they want, then the nearest; a food one must turn out to be mainly a place to eat or drink); the ones that fit come before Google's like her places, labelled "📍 Local favourite". Never in the ★ sheet, Admin's list or the "★ Feta Picks in <city>" count. Admin → Cities (`components/AdminCoverage.tsx`, `city_coverage()`) lists, per city, real people who searched there in the last 30 days next to how many of her places and local favourites it has; cities people use with fewer than 10 come first, in red.

**Featured in** (founder, 19 Nov 2026; `lib/server/featured.ts`): places the city's guides recommend (her sites in `data/event-sites.json`, never Zomato, Swiggy, District, BookMyShow or review sites), found once a day per city and category with Grounding with Google Search (about ₹3, shared through `events_cache`; the first search of the day starts it after replying, so it shows from the next search). Names become place IDs with the free IDs-only search inside the city's area; only the place ID, guide name and article link are kept. Up to 2 per new search are checked live, chosen like local favourites; the ones that fit come before Google's, labelled "📰 Featured in <guide>", with the article link and Google's Search chip in the details (the chip also shows on the list).

**Choose for me** (founder, 17 Nov 2026): a mood pop-up, then the cheese rolls and one place fills the screen; swipe left or Not this one for the next, swipe down or ✕ for Home, Let's go returns to Home with the Let's go sheet. Something new: a lesser-known place in their lists for something they shared; My usual: the best-loved one most like the places they love (`serves` on each pick says what it matched); Surprise me (`/api/surprise`): Gemini reads everything they've shared and suggests kinds of place they haven't chosen but would likely love (`readSurprise`), one search each through `curate` (`searches: 1`), never a place in their lists, saved, skipped or been, about ₹3–4 a tap.

**Plan a night** (founder, 17 Nov 2026; Saved → Want to try → Plan a night): tick 2 to 5 places, pick the day (today and every day of the coming week, founder 19 Nov 2026) and a start time; `/api/night-plan` reads the ticked places live (where, what kind, weekly hours; about ₹1.7 each, plus at most one nearby saved place to suggest) and `lib/night-plan.ts` orders and times them on the phone: each stop open for its whole visit, early closers first, an evening dinner not before 7 pm and after everything but drinks and dessert, the least travel and waiting. A place that doesn't fit is said plainly ("closed on Sundays") with Drop it / Start at… / Make it <day>; never left out quietly. The cheese trail (`components/NightTrail.tsx`): the stops where they really are on a pattern of streets (not a map), the route drawn in cheese, a small label per stop (time, name, why it's there) and the walk or ride between (rough, from distance). Edit: drag to reorder, swipe left to remove, times redo themselves. "Room for dessert?" offers one more place from their saved list a short walk away (never a second dinner). Route in Google Maps (every stop as a waypoint, by coordinates and place ID), Save (`saved_plans`: place IDs, day, start; city, country, time zone, currency) and Share (places and times only). The day after, Home asks "How was <day>?" for every stop (`CheckIn.tsx`), which fills Been.

**Who's in** (founder, 17 Nov 2026): friends reply In / Out (or vote for a plan) on a shared link with no sign-up; the person who shared sees the replies in the app. Saved → Plans lists their saved plans with the replies to their shares (`shares.plan_id`), and plans shared from elsewhere (Plan my evening, a pick) on their own; "N new" until they open "Who's coming <day>?" (`components/WhosComing.tsx`: each name with In or Out, Open the plan, Send the link again; `shares.replies_seen_at`). New replies also show on Home in the black pill at the top after the star lands ("Priya and Arjun are in · Saturday", `components/RepliesPill.tsx`), tap for Plans. Names are only what friends typed ("Someone" if none). No phone notifications.

**Feta's cheese** (founder, 18 Nov 2026; mock-up https://claude.ai/artifact/9QEDvVspmBzxqwhfdRTQpZ; `components/Mascot.tsx`): one character, called Feta, with arms and legs, each pose kept for one kind of moment: waves on Welcome and the name screen, a new pose per setup question; looks around (magnifier) while picks, plans and Feta Picks load; sorry when nothing fits; melts when the search itself failed (`Slot.failed`); thinks on Choose for me (asleep 11 pm–5 am) and in Ask Feta's typing; cheers when a plan is saved or a friend is in; shares a slice when a link is ready; takes a bite on "Loved it" and an empty Been; holds the strings in the cheese pull; goes mouldy beside a place saved over a month ago; "Aged N months" badge in You after a month. Props: shades on the Style tile, a suitcase on Plan a trip. Never on pick cards, place photos or Style looks; mould only on the cheese (it means "this is old", never "this place is bad"); no guilt nudges; privacy, sign-in and delete stay plain. The Ask tab and header use its face only (`Cheese.tsx`).

**Where events are looked for**: the sources the founder chose (Notion → 🌍 Event sites by city, in `data/event-sites.json`: by city, then region, then country, about 250 places; `eventSources` in `lib/server/events.ts`), found with Google Search grounding. Facts and links only: never scraped, never their words or photos. (The "This week in <city>" row on Home was removed on 19 Nov 2026: one search for the whole city brought events that fit no one, like AI summits.)

**Pull down for a fresh set** on the picks list and on Home (both lists at once) (`components/CheesePull.tsx`, founder 16 Nov 2026; `nextPicks` in `lib/picks-store.ts`): a cheese hangs from the pill at the top on strings that snap as you pull; letting go past the last snap replaces the list with the next places (the backup, else a new search, as "Show me more" which still adds below), and the pill says "8 new picks · ★ 1 Feta Pick". The pill (`components/TopPill.tsx`) is shared with the Feta Picks star.

## Ask Feta (chat) and trips
- `app/api/ask/route.ts`: a short brief (who they are, what Feta knows, the current trip, what it can do: search, itinerary of 1–3 days, trip route) and the model talks and decides. It is a real assistant, not a menu (founder, 18 Nov 2026): it helps with anything about going out even beyond Feta's options, suggests what they may not have thought of and a next step, and notes what it learns in profile lines. Plans with or for others (founder, 19 Nov 2026: a date night assumed her boyfriend likes what she likes, and came back all food): what Feta knows is about this person only, and what they've said about the people they go out with is listed apart (`people:` lines); before searching it asks, one question at a time with options, what it doesn't know yet (food and drinks, something to do, or both; the mood; what the others like), then acts (up to 2 searches per reply, run at once, best 3 each). It is a personal assistant for anything in life (founder, 19 Nov 2026: a gift idea, a tricky conversation, a busy week), answering briefly from what it knows and offering Feta's help when it fits; medical, legal and money decisions get general guidance and a pointer to a professional. Its past replies go back to it as the same JSON it answers in (as plain words it drifted into plain-words answers and lost its buttons). Its search takes any day and time (`at`: checked against each place's weekly hours; things to do with no hours, like a trail, pass) and "further" (`reach: "day_trip"`, up to 80 km) for hikes and day trips; it may name a landmark in the search note so Feta looks it up, but never presents a place as checked itself. Chat shows only places that match what was asked (`serves` includes "asked"), else says plainly why and offers further out or another day. Code checks only what the model kept getting wrong: a whole country, more than 3 days, or 2 days or more away from where they are ("3 days in Calicut") is always a route (a second, route-only call if needed); a search of a whole country asks for a city; the same route sent again keeps the trip's progress; day plans for a trip's cities go to its card. The current trip is found from the whole chat, not the last 12 messages. What it learns goes into profile lines (Undo; "Only for this trip").
- Trips (`lib/server/trip.ts`, `/api/trip`, `components/TripCard.tsx`, `/trip/<id>`): route with a two-line story per city (editable; the title follows the nights) → getting around (rough estimates, including getting there from home and back) → hotel budget (asked separately) and 3 stays per city → day plans per city, 3 days per tap near the chosen hotel, kept on the trip. Day plans for chat and trips both use `plan-days.ts` → picks engine in day-plan mode → `itinerary.ts`. Day-plan mode (founder, 16 Nov 2026: Calicut came back all food) also searches the sights (top attractions, history and culture, beach/park/nature) and breakfast and local food, plus one of their own interests for the evening; hours are checked per stop for its own day and time, and asking again finds the same places (no "already shown" exclusion). Day-plan sets are stored apart from everyday picks.

## Learning from people
Not my vibe (founder, 18 Nov 2026, a pop-up on the picks list, `reasonsFor` in `components/Picks.tsx`): skipping a pick offers reasons written from that place, each changing what Feta finds from then on, with Undo in the message: "Not into <kind>" (a `notinto:<Google type>` line; that type is never picked again, `taste.notInto` in the hard filters), "Too loud and crowded" / "Too fancy for me" (lines the ranking reads), "Too pricey" (budget down a level), "Too far" (distance down to below that place), "Been there". What it learned shows in You as lines "From a skip". Every change to answers goes through `saveTaste` (`lib/taste-client.ts`), used by You and skips alike.
You (`components/YourTaste.tsx`, founder 18 Nov 2026): rules Feta always follows (diet, budget, distance, drinks, who) are set with a tap and can't be removed with ✕ (✕ only on their own words; taste-card lines change by redoing the cards); cuisines and interests are chips; own words are filed by section (`you:food:` / `you:do:` line keys). Typed text that names a choice sets the choice (a diet is confirmed first; a cuisine or interest with a chip turns it on), the rest stays a note that is searched for; every change shows "Saved". Answers and cuisines regenerate the plain lines (`pickedUpLines`), and lines that no longer apply are marked removed.
Profile lines (`profile_lines`): from answers and taste cards, typed in their own words ("Something else", "Anything else", "Tell Feta what you like" on the picks list and in You), learned in chat, from tweaks. Lines in their own words are **searched for**, not only shown to the ranking. Places they've been (Saved → Been, check-ins) with Loved it / Fine / Not for me, how often, and notes feed the taste summary; loved places shape every new search in their category (a loved café shapes food, a loved pottery studio shapes things to do), 3 at a time taking turns through all of them (read live, about ₹1.7 each), including Show me more.

## Google, privacy and cost rules (never break)
- Store only Google place IDs (and the founder's places' locations, for up to 30 days). Show live Google data with the words "Google Maps" unchanged; events show Google's Search chip. Never use Google content to train or test AI models (the eval uses made-up places).
- No scraping of Zomato, District, Swiggy, BookMyShow or Meetup; link out. Published lists only as "Featured in" facts with links.
- 18+ check, itemised consent with a separate location toggle (off by default; "Use my location" turns it on), consent log, one-tap delete, grievance email. Sign out in You → Settings, for Google accounts only (an anonymous account would be lost); signing back in is "Already use Feta? Sign in" on Welcome. Nothing public by default. Diet never appears on anything shareable. No taste types or labels on people. Instagram data stays on the founder's Mac.
- Every record carries city, country, time zone and currency.
- Usage (founder, 17 Nov 2026): one `visits` row per person per day they open Feta (from the tab bar; nothing else recorded). Admin → Usage (`components/AdminUsage.tsx`, `usage_dashboard`, admins only): unique and new people, active today, days a week, retention by join week (day 1 / 7 / 30) for everyone and for people signed in with Google (the reliable one: anonymous accounts are one phone and browser), and the path from first open to coming back. Admins aren't counted. The Monday email gets the same (`people_and_retention`). Test visitors: opening Feta with `?qa=1` marks the account `profiles.is_test` (`lib/supabase.ts`); every admin number leaves them out by default ("Real people only" switch on Usage; the Monday email always).
- Cost guards: `PICKS_DAILY_LIMIT`, `PICKS_USER_DAILY_LIMIT`, `DAILY_BUDGET_INR` (Vercel); every paid call is counted (`lib/server/costs.ts`). A new food set costs about ₹12–20 (up to 4 Google searches, loved places read live, Gemini); reused sets cost only live re-checks.

## Testing
- Test runs in a browser (AI QA, Claude) open Feta with `?qa=1` so they never count as people.
- `npm run journey` (founder, 18 Nov 2026): a browser walks through Feta as someone new (welcome, name, the questions with options ticked and typed, city, Home, You) on made-up places, ₹0, about 20 seconds, and checks every option is on screen, what they pick or type is saved and shows in You, and Home has picks. Must pass before pushing any change to screens or onboarding (`scripts/journey.ts`; it starts its own test server on port 3100, so stop any other `next dev` in this folder first). When a tester finds a screen bug, add a check for it.
- `npm run eval`: the quality check (must pass). `FAKE_PLACES=1` dev server: made-up places that look like a real city (`lib/server/fake-places.ts`), fake ranking, no events or photos, ₹0. Chat still calls Venice (a few paise).
- Live Google only when the change depends on real data: one short run, with her OK, and delete test accounts after.

Installable (founder, 18 Nov 2026): `app/manifest.ts`, icons in `public/icons/`, `app/icon.svg` and `app/apple-icon.png` (the cheese); You shows how to add Feta to the home screen (`components/InstallFeta.tsx`, an Install button where Android offers one). On an iPhone, Home shows "Put Feta on your home screen · How?" under the greeting (`components/IphoneInstall.tsx`): three steps with pictures, gone once installed or after ✕ (Apple lets no website offer an install button). An installed Feta updates itself: back from the background, it checks `/api/version` against the deploy it came from and reloads quietly at a calm moment (a main screen, nothing open or being typed; `components/FreshVersion.tsx`). App stores later (Sign in with Apple needed, and native features such as notifications so Apple doesn't reject it as a website wrapper).
