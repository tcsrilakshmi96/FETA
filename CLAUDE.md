# Feta — project guide for Claude Code

Feta is a personal AI lifestyle companion that learns a person's taste and decides for them: places to eat and drink, things to do, style, and trips. **Personalised curation is the product** (founder, 15 Nov 2026): what people tell Feta must decide what it finds.

This page holds the **current rules only**. The reasons and history behind them are in `docs/decisions.md` (add new decisions there, dated). If the two disagree, this page wins. Designs: `design/README.md`, `design/DATA_CONTRACT.md`, `design/prototype/Feta App v2.dc.html`; the design wins for look, this page for data, privacy and behaviour. Redesign mock (14 Nov 2026): https://claude.ai/artifact/StSCbvNLSQ4uz5LYjHiw4v

## Working with the founder
- Srilakshmi is non-technical. Explain in plain English, one short paragraph at a time. Think about the whole flow and the root cause before building; mock up UX changes first.
- **No stacking.** If a fix needs a special case on top of other logic, the base is wrong: change the base and delete what it replaces.
- **One change per commit.** She tests the whole set together on https://askfeta.com (auto-deploys from main; feta-beige.vercel.app still works), so push when the set is done and tested.
- **Quality check first.** Every change to picks must pass `npm run eval` (realistic profiles against made-up places, ₹0). Add a profile when a tester finds a new kind of miss. A live run (`EVAL_LIVE=1`, about ₹50) only with her OK.
- Ask before adding a paid service, creating accounts, deleting anything, or spending money on tests. Never put keys or secrets in code or commits (`.env.local`, listed in `.env.example`). Migrations go on her clipboard for the Supabase SQL Editor only after `npm run sql-check` passes (Postgres's own parser, functions included, and the 255 limit on pattern repeats; part of the eval); after adding one, run `npm run schema` (the eval fails until you do), so Admin's database check (`components/AdminHealth.tsx`, `schema_objects()`) names any migration that never ran.
- Suggest automations (n8n, Vercel, Claude scheduled tasks) in a line or two when a step could be automated; don't set them up without her go-ahead.

## Stack
Next.js 16 (App Router; `useParams`/`useSearchParams` need `<Suspense>`), Supabase (auth, RLS, Postgres), Vercel. Google Places API (New) for places; Gemini 3.5 Flash ranks places and reads taste; Venice (`claude-sonnet-5-5` since 23 Nov 2026, `lib/server/venice.ts`, cost counted from each reply's tokens) runs Ask Feta only (its replies, options and trip routes); Venice credits are limited, so everything else, Style and the trip card included, is on Gemini (founder, 23 Nov 2026). **Venice never receives Google content**; Gemini gets only Feta's own data plus live place descriptions. What Feta learned from the places someone loves (`loved:` lines, e.g. "Burmese") is Feta's own reading and does reach Venice, so chat stays personal (founder, 24 Nov 2026).

## Flow
Welcome (3 cards, 18+ on the last) → `/start` (first name, required; "What do you want from Feta?": Places to eat and drink, Things to do, What to wear, Plan a trip) → `/location?setup=1` (their location or a city, then area / anywhere; before the questions since 19 Nov 2026, so they show that city's money and cuisines) → `/questions` (at most 4 screens, only for what they chose: basics; places they love, no limit, then "Recommend them to people like you?"; cuisines (all 12 tiles, Indian and world in turn; up to 4 + Something else, where a cuisine Feta has a tile for counts as chosen and other words stay as "Also loves …") and things to do (+ own words; "Try something new" groups true in every city: Classes and workshops, Tastings, Hikes and trails, Outdoor adventures, Wellness, each opening optional specifics such as Pottery or Horse riding, `components/InterestChips.tsx`, the same on every screen; a group alone means any kind, a specific one is searched for itself, founder 21 Nov 2026); one vibe card) → Home. A trip alone asks no category questions; a category they didn't choose asks its questions the first time it's opened (`components/FirstTime.tsx`). Sign-in (Google) is offered once on Home after the first picks.

Home (founder, 24 Nov 2026: "too crowded… one category shouldn't overpower the other"; option F): date · area ▾ with a small BETA, then ★ Favourites and You; one search bar ("Search a place, a class or a piece…", opens `/search`); Today/Tonight · This weekend with Choose for me (its cheese stays) beside it; then four equal squares, Eat, Do, Wear, Trip, each with its top pick or a "Tell Feta what you like" for a category they didn't choose (only the chosen are searched; each kind keeps its colour: saffron, turquoise, rose). No greeting, no mascot on Home's tiles, no light/dark switch (You → Settings), no Feedback button; Plan my evening lives in the Eat and Do lists (and Choose for me's "What's after?"). Every screen has a plain background (no glows); light mode is a warm cream-orange (#fbe3cc), with sheets, switches and the tab bar a lighter cream, never white. Tabs: Picks + Style, Saved (Want to try, Been, Plans), Ask (🧀); You from the round button. "How was it?" is a pop-up (after a plan: "How was Saturday?" for every stop); feedback is a pop-up, never a button on the screens (founder, 24 Nov 2026; `components/Feedback.tsx`): "How's Feta so far?" with five faces, an optional note and the testers' Google Form link, after they save, share or plan something or on their third day, at most once a week, never over another pop-up or during setup, and "Send feedback" in You any time; from the second visit, a card asks testers to fill in the Google Form (`components/TesterForm.tsx`, https://forms.gle/bfadwNw1mVzT3uLj8; Later brings it back every visit until they open it; never a lock, never on top of another pop-up, after "Save your taste" has had its turn).

## How picks work
One path for every caller (Picks, Home, Ask Feta, Plan my evening, trips; Plan my evening's nearby search too since 18 Nov 2026), in `lib/server/`:
1. **What they want** (`intents.ts`): every choice becomes an intent: what they asked for right now (chat note, tweaks), then everything they've shared **taken in turn** (a favourite cuisine or interest, their own words, what their loved places have in common (`taste-reader.ts`, Gemini, kept in memory an hour), then the next of each), so no kind crowds out another; taste-card sides last. The more they share, the more each set reflects it. Search words and which Google types count as a match live **only** in `catalog.ts`; the eval fails if a choice on screen has no entry.
2. **Find** (`curate.ts`): Feta's lists first (founder, 22 Nov 2026: "lists first, Google to fill gaps"): her places, local favourites, Featured in and Feta users' favourites are checked live before any Google search, and a choice 2 or more of them already serve (by Google type) isn't searched on Google that set (`LIST_ENOUGH`, `fromLists`), and its search goes to the next choice; every choice a list place is counts as looked for that set (`looked` in `curate.ts`), so it gets its promised spot, is held to a few of one kind, and is named in the banner when nothing fits. Then one Google text search per remaining intent, up to 4 per set (`MAX_SEARCHES`), plus what's popular nearby when there's room (places to eat and drink, or things to do: attractions, galleries, theatres, parks, bowling). If more were chosen, they take turns across sets: never searched first (a choice just added in You comes in the very next set), then the ones searched longest ago (`pick_sets.searched`, the last day's sets). Their distance is a hard limit, never stretched (founder, 19 Nov 2026); too few within it means a shorter list that says so. The one exception: hikes and outdoor adventures (`far` in `catalog.ts`) at the weekend, and their events, may be up to a day trip away (80 km), and the card says "34 km away · a trip out" (founder, 21 Nov 2026). **Things to do use exactly the same steps as food** (founder, 17 Nov 2026): what they shared, their loved places, popular nearby, the new-or-usual lean, Feta Favourites.
3. **Hard filters in code** (`picks.ts` `applyHardFilters`): diet, budget, distance, drinks, opening hours, closed, already saved/skipped/been, and quality (`poorlyKnown`: rated below 3.8, or fewer than 5 reviews). Never left to the AI.
4. **Rank**: Gemini orders the places for this person and says which intents each "serves" (it can confirm, never add, a match). Test mode uses `fakeRank`.
5. **Keep the promise** (`selectPicks`): each thing they chose gets its best place among the 8 when one passed (even if very popular); then every Feta favourite that is for something they chose (founder, 23 Nov 2026: "why is the AI thinking a sports bar fits a vegetarian?"; before, a curated place counted unless the ranking objected), best fit first, with no set number per source (founder, 19 Nov 2026: "think about what fits them the best… keep Google search the last"); places for their choices fill at least half; then the ranking. **No filler** (founder, 19 Nov 2026: "the whole point of this app is showing customised suggestions"): once they've shared anything, every place shown or kept as backup is for something they chose, said or love, curated places included; what's merely popular nearby never fills a set, and a short list says so ("Only 3 places really fit you here tonight. No weak filler."). Global fast-food chains (Taco Bell, KFC, McDonald's…; `fastFoodChain` in `picks.ts`) only when they're the only place found for something they asked for (founder, 21 Nov 2026). One branch per chain, at most 1–3 very popular places (novelty), a few of one kind at most. Shown in this order: her places, loved by Feta users, local favourites, Featured in, then Google's, best fit first within each (founder, 19 Nov 2026). Anything chosen that found nothing is said plainly in the banner ("No Korean near you tonight"; words in reasons and banners keep capitals only for a people or a place).

A request can narrow itself, in the engine and nowhere else (founder, 18 Nov 2026: one path for every screen): `only: "asked"` keeps just the places that match its note (Ask Feta, Plan my evening's after-dinner search; no everyday filler, no events); `at` checks a day and time; `reach` changes the distance for that one ask (`walk` near a dinner, `day_trip` up to 80 km); `searches` caps Google searches. Screens never re-filter or re-rank results themselves.

**Things to do are led by what's on** (founder, 19 Nov 2026: "lets not only focus on places, lets focus on events and things to do"): for each thing they chose, said or love (comedy, karaoke, pottery, hiking, pop-ups…), one Google Search grounding call finds events of that kind tonight or this weekend in the city (at most 2 new ones per set since 23 Nov 2026, taking turns across sets; kinds already searched in the city are free and always used) (`findEvents` with a kind; about ₹3, shared by everyone there into the same thing through `events_cache`, 6 h tonight / 24 h otherwise since the cost cut of 23 Nov 2026), with no set number of searches or events. Events that pass the hard filters (date, budget, distance via the venue) come first, taking turns across what they're into, each serving the thing it was found for; places fill the rest. The first search of the day waits up to 15 s for them; events found after that join the stored set at the top (places they push out become backup), and the phone asks once more about 20 s later and shows them (live check, 23 Nov 2026: 7 Bengaluru workshops took 18 s and were left off for 3 hours). Things booked ahead (the "Try something new" choices, `ahead` in `catalog.ts`) are looked for across the coming 7 days and stay while still ahead (founder, 21 Nov 2026: "dated events instead of venues, that's when it's truly curated").

A recent set (3 h tonight / 12 h weekend, same place and taste) comes back by re-checking its places and events live, with no new search and not counted as a search (founder's testers, 21 Nov 2026); if most no longer pass, it searches afresh. Then `engine.ts` adds verdicts, reasons (Gemini's line only when it names something the place really serves, else Feta's own, "Because you love Thai & SE Asian food", else none; a vibe or taste card is never a reason, founder's tester 22 Nov 2026: "reads as fake personalization"; `becauseFor` in `curate.ts`), stores the set (place IDs and Feta's words only) and builds cards. Sets are reused for 3 h (tonight) / 12 h (weekend), keyed by place **and a taste fingerprint**, so any change in taste searches again; the phone also drops its kept picks (`forgetPicks`). The phone keeps each list it has shown for an hour, also across a reload (`feta.picks.kept`), so it comes back free and still shows past the day's limit (founder, 24 Nov 2026); never longer, as Google allows.

Rules inside the filters:
- **Vegetarian, veg + eggs, Jain, vegan**: Google's "serves vegetarian food" must be yes; **in India a place with no answer also passes**, with the chip "Veg options · not confirmed, check with staff"; abroad it doesn't. Places mainly about meat or fish never pass (type, name in the common languages of place names, such as churrasqueira or marisqueira, and Gemini's flag). Never "pure veg"; never say food is safe for a diet.
- **Pescatarian**: places mainly about meat are dropped. **No beef / no pork**: places mainly about it are dropped. Halal can't be checked: a "not confirmed" chip only.
- **No alcohol**: places whose main type is a bar, pub, club or brewery are dropped (a restaurant with a bar is fine).
- **Things to do** never show a bar (founder, 19 Nov 2026: bars belong in Food & drinks; karaoke and live music nights there come as events), nor a café or restaurant unless it matched something they're into that happens there (board games, comedy, live music), nor an office or service (tour or travel agency, event planner; 23 Nov 2026), nor a place Google has no type for unless its name says it's what was searched. Hidden bars and rooftops are searched in Food & drinks (`drinkPlace` in `catalog.ts`).
- Spend is a range: the levels they ticked (`spendRange` in `lib/onboarding.ts`; the top is the most they'll spend and a place clearly above it is dropped; the bottom is never a filter (founder, 19 Nov 2026: a great cheaper place still fits); "Depends on the day" stands alone and means no limit). Levels travel between currencies (`lib/currency.ts`); a place or event with no price passes, except fine dining, which counts as the top level. Cheaper and Fancier move the range a level. The first slot follows the city's clock (founder, 24 Nov 2026: "what if someone wants to go for breakfast or lunch?"): from 5 pm to 5 am it reads "Tonight" and means open now; earlier it reads "Today" and means open for at least an hour in the next 5 hours (breakfast, a museum, lunch; a park or trail with no hours on Google counts), while an ask meant for this evening (Ask Feta's "dinner tonight", Plan my evening; `evening`) keeps the evening window, open an hour between 7 and 10 pm, the AI told it's daytime there (`tonightMeansNow`, `hoursAhead`, `slotWord` in `picks.ts`; `firstSlotName` in `lib/slot-label.ts` on Home and Picks; Choose for me uses the same lists). The value stays `tonight` in code; a list made by day is reused in the evening only for what's still open. Weekend: Sat or Sun hours.
- Plan my evening (`lib/plan.ts`, 23 Nov 2026): each stop's role comes from what the place is: dinner a place to eat a meal (never a bakery, café or dessert shop), after dinner drinks or dessert, something to do an event or a place to go (a café or bar only when something they chose happens there).
- Verdicts: "Good if you're nearby" by default, "Worth a detour" at most once per set, "Skip unless…" for a real, checkable compromise. Chips are written by code from facts.
- Small cities (< 300k) also take only places the ranking chose. Someone who hasn't shared anything yet gets what's popular nearby.

**Feta Favourites**: the founder's places (`founder_places`, FETA PICK with her note: her own list, plus any place she marks Loved it in the app, kept in step by `syncFounderLoved` whenever she rates one) and places Feta users loved and chose to recommend (`pick_actions.recommend`; `feta_favourites()` puts people with a shared cuisine or interest first; `feta_love_counts()`). Up to 3 founder places within their distance (6 until the cost cut of 23 Nov 2026) (the ones whose name and note match most of what they want; at most 1 that matches nothing, nearest first, since each live check costs about ₹1.7) and 1 community place are checked live per new search, before Google's search; a list place Google's search finds anyway is labelled for free. Where her places are is kept for up to 30 days, as Google allows (`founder_places.lat/lng/located_at`, looked up when missing or older than 25 days, about ₹0.4 each; forgotten nightly after 30 days; `lib/server/feta-places.ts`). The founder's places may come back even if the person has been or saved them; only a skip hides one. The ★ button next to You on Home (`components/FetaStar.tsx`; every time Home shows, when the city has her places, the pill at the top says "★ Feta Picks in <city>" and the star flies into the button) opens polaroids, her note handwritten (`/api/feta-picks`, `components/FetaPicksSheet.tsx`), of her places and favourites from people with a similar taste that fit their diet, budget and distance, nearest first (up to 10 checked live when opened, about ₹20, kept on the phone an hour; closed places say "Closed now"). Cards show "♥ Loved by N Feta users"; never who. Loves count only from people signed in with Google who aren't test accounts (`real_people`; security audit, 24 Nov 2026), for places and brands alike.

**Local favourites** (founder, 19 Nov 2026): about 2,700 places locals recommend in 187 cities, from her research (an Excel built from Reddit threads and page reads), kept in `founder_places` with `source = 'local'`: place ID, name, kind, city only; no note, nothing quoted from Reddit or Zomato, no hours or prices (Google's live data decides). Up to 4 per new search are checked live, before Google's search (what they want, by the place's tags, then the nearest; a food one must turn out to be mainly a place to eat or drink); the ones that fit come before Google's like her places, labelled "📍 Local favourite". Never in the ★ sheet, Admin's list or the "★ Feta Picks in <city>" count. Admin → Cities (`components/AdminCoverage.tsx`, `city_coverage()`) lists, per city, real people who searched there in the last 30 days next to how many of her places and local favourites it has; cities people use with fewer than 10 come first, in red.

**What a list place is** (founder, 24 Nov 2026: Jeremy in New York, Mexican food and live music, never saw Tacocina, Birdland or Smalls; Feta guessed from names): every place on her lists and every local favourite has several tags in Feta's own words, written by Claude here (`founder_places.tags`, cuisine and interest ids from `catalog.ts` plus words like "tacos", "jazz club", "landmark"; `set_place_tags`), and Featured in places get theirs in the daily search; which list places are checked live is decided by the tags (`listFit` in `lib/server/list-tags.ts`), and a checked one counts as a choice by its tags as by a Google type (`listServes`; whole tags and words only, so "steak" is never tea; a search's words count in the name too). A list place must also fit their vibe (founder, 24 Nov 2026, after the Barbara test: "quiet, elegant" got a casual chain as a Feta Pick): from their own words, the vibe card and "Too loud and crowded" skips, someone quiet never gets one tagged buzzing, night out or club, someone elegant never one tagged casual, hole-in-the-wall or pub, and a hole-in-the-wall person never dressed-up fine dining (`vibeOf`, `vibeClash` in `list-tags.ts`); with nothing said, nothing is ruled out. A new list place is tagged when it's added.

**Featured in** (founder, 19 Nov 2026; `lib/server/featured.ts`): places the city's guides recommend (her sites in `data/event-sites.json`, never Zomato, Swiggy, District, BookMyShow or review sites), found once a day per city and category with Grounding with Google Search (about ₹3, shared through `events_cache`; the first search of the day starts it after replying, so it shows from the next search). Names become place IDs with the free IDs-only search inside the city's area; only the place ID, guide name and article link are kept. Up to 4 per new search are checked live, only ones whose tags match what they want (2 for someone who hasn't shared anything; founder, 24 Nov 2026: "hardly we see any featured lists"); the ones that fit come before Google's, labelled "📰 Featured in <guide>", with the article link and Google's Search chip in the details (the chip also shows on the list).

**Choose for me** (founder, 17 Nov 2026): a mood pop-up, then the cheese rolls and one place fills the screen; swipe left or Not this one for the next (taking turns across kinds), swipe down or ✕ for Home, Let's go returns to Home with the Let's go sheet. Something new: a lesser-known place in their lists for something they shared; My usual: the best-loved one most like the places they love (`serves` on each pick says what it matched); Surprise me (`/api/surprise`): Gemini reads everything they've shared and suggests kinds of place they haven't chosen but would likely love (`readSurprise`), one search each through `curate` (`searches: 1`), never a place in their lists, saved, skipped or been, about ₹3–4 a tap.

**Plan a night** (founder, 17 Nov 2026; Saved → Want to try → Plan a night): tick 2 to 5 places, pick the day (today and every day of the coming week, founder 19 Nov 2026) and a start time; `/api/night-plan` reads the ticked places live (where, what kind, weekly hours; about ₹1.7 each, plus at most one nearby saved place to suggest) and `lib/night-plan.ts` orders and times them on the phone: each stop open for its whole visit, early closers first, an evening dinner not before 7 pm and after everything but drinks and dessert, the least travel and waiting. A place that doesn't fit is said plainly ("closed on Sundays") with Drop it / Start at… / Make it <day>; never left out quietly. The cheese trail (`components/NightTrail.tsx`): the stops where they really are on a pattern of streets (not a map), the route drawn in cheese, a small label per stop (time, name, why it's there) and the walk or ride between (rough, from distance). Edit: drag to reorder, swipe left to remove, times redo themselves. "Room for dessert?" offers one more place from their saved list a short walk away (never a second dinner). Route in Google Maps (every stop as a waypoint, by coordinates and place ID), Save (`saved_plans`: place IDs, day, start; city, country, time zone, currency) and Share (places and times only). The day after, Home asks "How was <day>?" for every stop (`CheckIn.tsx`), which fills Been.

**Who's in** (founder, 17 Nov 2026; "Stop sharing" on the share sheet and in Who's coming deletes a link, 22 Nov 2026): friends reply In / Out (or vote for a plan) on a shared link with no sign-up; the person who shared sees the replies in the app. Saved → Plans lists their saved plans with the replies to their shares (`shares.plan_id`), and plans shared from elsewhere (Plan my evening, a pick) on their own; "N new" until they open "Who's coming <day>?" (`components/WhosComing.tsx`: each name with In or Out, Open the plan, Send the link again; `shares.replies_seen_at`). New replies also show on Home in the black pill at the top after the star lands ("Priya and Arjun are in · Saturday", `components/RepliesPill.tsx`), tap for Plans. Names are only what friends typed ("Someone" if none). No phone notifications.

**Feta's cheese** (founder, 18 Nov 2026; mock-up https://claude.ai/artifact/9QEDvVspmBzxqwhfdRTQpZ; `components/Mascot.tsx`): one character, called Feta, with arms and legs, each pose kept for one kind of moment: waves on Welcome and the name screen, a new pose per setup question; looks around (magnifier) while picks, plans and Feta Picks load; sorry when nothing fits; melts when the search itself failed (`Slot.failed`); thinks on Choose for me (asleep 11 pm–5 am) and in Ask Feta's typing; cheers when a plan is saved or a friend is in; shares a slice when a link is ready; takes a bite on "Loved it" and an empty Been; holds the strings in the cheese pull; goes mouldy beside a place saved over a month ago; "Aged N months" badge in You after a month. Props: shades on the Style tile, a suitcase on Plan a trip. Never on pick cards, place photos or Style looks; mould only on the cheese (it means "this is old", never "this place is bad"); no guilt nudges; privacy, sign-in and delete stay plain. The Ask tab and header use its face only (`Cheese.tsx`).

**What's on in her guides** (founder, 22 Nov 2026: a search shows only a few lines of Time Out's "this month" post): once a day per city, the first search starts a Google search for her guide sites' current "what's on" posts (its Search chip goes with the events) and then Gemini reads those posts in full (URL context, tested on Miami: 20 events in 25 s; `lib/server/guide-events.ts`, about ₹2–3 a post, shared through `events_cache` for 20 h), listing every event in the next 14 days with the link the post gives (tickets, Instagram, organiser) or the post itself; these come first for each thing they're into that they're about, as "Found on <site> · Feta's guide list". Facts and links only; never District, BookMyShow, Meetup, Zomato or Swiggy.

**Free event feeds first** (founder, 23 Nov 2026; `lib/server/event-feeds.ts`): where a city publishes its events as open data, Feta reads them directly (₹0) for the kinds the feed can tell apart, before any paid search: Paris ("Que faire à Paris", Ville de Paris, ODbL, by its own categories, never the children's programme, seasons or giveaways) and Taiwan's main cities (Ministry of Culture: music, theatre, dance, exhibitions). Ticketmaster, SeatGeek, Skiddle and Korea's TourAPI need keys in her name and plug in there. **Where events are looked for**: the sources the founder chose (Notion → 🌍 Event sites by city, in `data/event-sites.json`: by city, then region, then country, about 250 places; `eventSources` in `lib/server/events.ts`), found with Google Search grounding: the first search looks only on those sites, a wider one only when they have nothing of that kind (founder, 22 Nov 2026), and an event from her list says "📍 Found on <site> · Feta's guide list" (`fromList`, `curatedLabel`). An event's link may be its own page, the guide's post about it, or the organiser's Instagram post ("See it on Instagram"; "Tickets on" only for ticket sites, `lib/event-links.ts`), and something running several days (a pop-up, a market) shows while it's on (`endDate`; "Until Sun 30", "ON NOW") (founder, 22 Nov 2026: London's pop-ups are only on Instagram). Few of these sites have an official feed (checked 22 Nov 2026: Ticketmaster's Discovery API and Fever's event search can be read directly; most city guides, District, BookMyShow, Luma and Eventbrite can't). Facts and links only: never scraped, never their words or photos. (The "This week in <city>" row on Home was removed on 19 Nov 2026: one search for the whole city brought events that fit no one, like AI summits.)

**Search** (founder, 23 Nov 2026; mock https://claude.ai/artifact/CdKt77g9QacuYG7NgEvZw9): a round Search button beside Favourites and You on Home (nothing on Home moves; the journey checks the tiles stay put) opens `/search` (`components/Search.tsx`): one box; words for clothes (`guessSearch` in `lib/search.ts`, no AI) put "A piece to buy" first, anything else "A place or something to do"; both are always offered, recent searches on the phone only. A place or activity opens the picks list as a search (`/picks?q=…&c=…`, titled “…”, Food & drinks / Things to do one tap apart, no Tweak, Plan my evening or taste box), through the engine's `search` mode: only what they typed, searched as typed (one Google search, no taste reading, list places checked only when their name or note matches it, events of that kind for things to do, nothing from today's lists left out), their usual rules held for a kind of place; a place whose name they typed (`namedPlace` in `curate.ts`; a search of kind words only, like "rooftop bar", names nothing) always shows first, with "You searched for it." and every usual rule it breaks on the card ("Above your usual budget", "Not open tonight", "May not suit how you eat · check with staff"; `rulesBroken` in `picks.ts`, the same list the hard filters use; never a diet promise). A search never changes their taste and counts as one of the day's searches. A piece opens Brands (`/style/brands?q=…`, also a box under its heading): brands in their country, in any style and within their budget, whose name or research notes (cues, the sample piece) have every word typed (`piecesMatch`, free; else the closest, said so), each linking to its own store searched for the piece with Google (`pieceLink`; stock never promised). The picks list's taste box is "Add to your taste" (kept for good), so the two boxes read differently.

**Pull down for a fresh set** on the picks list and on Home (both lists at once) (`components/CheesePull.tsx`, founder 16 Nov 2026; `nextPicks` in `lib/picks-store.ts`): a cheese hangs from the pill at the top on strings that snap as you pull; letting go past the last snap replaces the list with the next places (the backup, else a new search, as "Show me more" which still adds below), and the pill says "8 new picks · ★ 1 Feta Pick". The pill (`components/TopPill.tsx`) is shared with the Feta Picks star.

## Style (beta, founder 20–23 Nov 2026; the full rule list is `docs/style-spec.md`, the mock https://claude.ai/artifact/UUy8nfAqGToqU8iYfKxKFB)
Brand discovery and what to wear, in the app's own look with a small BETA tag and her inspiration videos' motion (clothesline, pulsing dots, lineup, hanging tags, looks walking in and out; never a giant word behind a figure). ## Ask Feta (chat) and trips
- `app/api/ask/route.ts`: a short brief (who they are, what Feta knows, the current trip, what it can do: search, itinerary of 1–3 days, trip route) and the model talks and decides. It is a real assistant, not a menu (founder, 18 Nov 2026): it helps with anything about going out even beyond Feta's options, suggests what they may not have thought of and a next step, and notes what it learns in profile lines. Plans with or for others (founder, 19 Nov 2026: a date night assumed her boyfriend likes what she likes, and came back all food): what Feta knows is about this person only, and what they've said about the people they go out with is listed apart (`people:` lines); before searching it asks, one question at a time with options, what it doesn't know yet (food and drinks, something to do, or both; the mood; what the others like), then acts (up to 2 searches per reply, run at once, best 3 each). It is a personal assistant for anything in life (founder, 19 Nov 2026: a gift idea, a tricky conversation, a busy week), answering briefly from what it knows and offering Feta's help when it fits; medical, legal and money decisions get general guidance and a pointer to a professional. Its past replies go back to it as the same JSON it answers in (as plain words it drifted into plain-words answers and lost its buttons). Its search takes any day and time (`at`: checked against each place's weekly hours; things to do with no hours, like a trail, pass) and "further" (`reach: "day_trip"`, up to 80 km) for hikes and day trips; it may name a landmark in the search note so Feta looks it up, but never presents a place as checked itself. Chat shows only places that match what was asked (`serves` includes "asked"), else says plainly why and offers further out or another day. Code checks only what the model kept getting wrong: a whole country, more than 3 days, or 2 days or more away from where they are ("3 days in Calicut") is always a route (a second, route-only call if needed); a search of a whole country asks for a city; the same route sent again keeps the trip's progress; day plans for a trip's cities go to its card. The current trip is found from the whole chat, not the last 12 messages. Setup and card taps reach the brief as leanings, never facts to state back; a trip's start and who only when they said them, and it never picks a destination they didn't name (22 Nov 2026). Something for this weekend is offered with "Add to my weekend", never added on its own. What it learns goes into profile lines (Undo; "Only for this trip"; "Just for today" for something true only tonight, which the model marks itself, `lib/profile-scope.ts`). Lines about the people they go out with (`people:`) reach only Ask's brief, never everyday picks.
- Trips (`lib/server/trip.ts`, `/api/trip`, `components/TripCard.tsx`, `/trip/<id>`): route with a two-line story per city (editable; the title, "7 nights in Japan", and the chat header are built from the saved trip, `tripTitle`, `tripHeader`) → getting around (rough estimates, including getting there from home and back) → hotel budget (asked separately) and 3 stays per city → day plans per city, 3 days per tap near the chosen hotel, kept on the trip. Day plans for chat and trips both use `plan-days.ts` → picks engine in day-plan mode → `itinerary.ts`. Day-plan mode (founder, 16 Nov 2026: Calicut came back all food) also searches the sights (top attractions, history and culture, beach/park/nature) and breakfast and local food, plus one of their own interests for the evening; hours are checked per stop for its own day and time, and asking again finds the same places (no "already shown" exclusion). Day-plan sets are stored apart from everyday picks.

## Learning from people
Not my vibe (founder, 18 Nov 2026, a pop-up on the picks list, `reasonsFor` in `components/Picks.tsx`): skipping a pick offers reasons written from that place, each changing what Feta finds from then on, with Undo in the message: "Not into <kind>" (a `notinto:<Google type>` line; that type is never picked again, `taste.notInto` in the hard filters), "Too loud and crowded" / "Too fancy for me" (lines the ranking reads), "Too pricey" (budget down a level), "Too far" (distance down to below that place), "Been there". What it learned shows in You as lines "From a skip". What the places they love have in common ("Burmese", read by `taste-reader.ts`) shows in You as "Learned from places you love" (`loved:<food|do>:<label>` lines from 'loved'), ✕ stops Feta searching for it (founder, 21 Nov 2026). Every change to answers goes through `saveTaste` (`lib/taste-client.ts`), used by You and skips alike.
You (`components/YourTaste.tsx`, founder 18 Nov 2026): rules Feta always follows (diet, budget, distance, drinks, who) are set with a tap and can't be removed with ✕ (✕ only on their own words; taste-card lines change by redoing the cards); cuisines and interests are chips; own words are filed by section (`you:food:` / `you:do:` line keys). Typed text that names a choice sets the choice (a diet is confirmed first; a cuisine or interest with a chip turns it on), the rest stays a note that is searched for; every change shows "Saved". Answers and cuisines regenerate the plain lines (`pickedUpLines`), and lines that no longer apply are marked removed.
Profile lines (`profile_lines`): from answers and taste cards, typed in their own words ("Something else", "Anything else", "Tell Feta what you like" on the picks list and in You), learned in chat, from tweaks. Lines in their own words are **searched for**, not only shown to the ranking. Places they've been (Saved → Been, check-ins) with Loved it / Fine / Not for me, how often, and notes feed the taste summary; loved places shape every new search in their category (a loved café shapes food, a loved pottery studio shapes things to do), 2 at a time taking turns through all of them (read live, about ₹1.7 each), including Show me more.

## Google, privacy and cost rules (never break)
- Store only Google place IDs (and the founder's places' locations, for up to 30 days). Show live Google data with the words "Google Maps" unchanged (hours read "Open now · closes 21:00 · checked on Google Maps", founder 22 Nov 2026); events show Google's Search chip. Never use Google content to train or test AI models (the eval uses made-up places).
- No scraping of Zomato, District, Swiggy, BookMyShow or Meetup; link out. Published lists only as "Featured in" facts with links.
- 18+ check, itemised consent with a separate location toggle (off by default; "Use my location" turns it on), consent log, one-tap delete, grievance email. Sign out in You → Settings, for Google accounts only (an anonymous account would be lost); signing back in is "Already use Feta? Sign in" on Welcome. What the phone keeps belongs to one account (`feta.owner`, `claimPhone` in `lib/supabase.ts`): when another account opens Feta there (an installed Feta and the browser keep separate copies; a switched Google account; a shared phone), the copy is cleared and Feta starts from Welcome, which brings back that account's own (founder, 21 Nov 2026). Nothing public by default. Diet never appears on anything shareable. No taste types or labels on people. Instagram data stays on the founder's Mac.
- Every record carries city, country, time zone and currency.
- What everyone shares is written only by Feta's server (backend audit, 23 Nov 2026): the events cache (its Google chip is shown as given) and the cost log go through functions that check the server key (`save_events_cache`, `log_costs`, like `save_brand_lookup`); no policy lets a signed-in person write them. A friend opening a shared place with no account counts toward everyone's day and has a small budget of their own (`LOOKUP_DAILY_BUDGET_INR`, ₹200), refused once either is spent or can't be read (`/api/place`). Writes only the server makes use their own key (`FETA_WRITE_KEY`, `write_keys`), never the n8n report key. A share holds only what Feta made, checked against Feta's own records (`check_share`: events from `found_events`, her note on her own places, a day or date as the title), a link takes at most 30 voters, and a share page links an event out only to a site Feta knows (`trustedEventLink`: her guides, the known ticket and listing sites, Instagram, Google), else "Search it on Google" (founder, 24 Nov 2026). Google's Search chip is shown minus anything that runs code (`safeChip`). A pick set can't be changed after it's made except its places; a visit is always for today.
- Usage (founder, 17 Nov 2026): one `visits` row per person per day they open Feta (from the tab bar; nothing else recorded). Admin → Usage (`components/AdminUsage.tsx`, `usage_dashboard`, admins only): unique and new people, active today, days a week, retention by join week (day 1 / 7 / 30) for everyone and for people signed in with Google (the reliable one: anonymous accounts are one phone and browser), and the path from first open to coming back. Admins aren't counted. The Monday email gets the same (`people_and_retention`). Test visitors: opening Feta with `?qa=<tester code>` (`QA_CODE` in `.env.local`, checked by the database against its hash; since the audit of 23 Nov 2026 `?qa=1` no longer counts, as anyone could move into the test budget) marks the account `profiles.is_test` through `mark_test()`, the only way to change it (`lib/supabase.ts`); every admin number leaves them out by default ("Real people only" switch on Usage; the Monday email always).
- Gemini alert (founder, 21 Nov 2026): `/api/health` makes one tiny Gemini call (about ₹0.15) for Admin (red box when it's out of credit or failing, `components/AdminHealth.tsx`) and for her n8n check (`x-report-key`), which emails her.
- Cost guards: `PICKS_DAILY_LIMIT`, `PICKS_USER_DAILY_LIMIT`, `DAILY_BUDGET_INR`, `USER_DAILY_BUDGET_INR` (Vercel); every paid call is counted (`lib/server/costs.ts`, one read: `budget_today()`). **One gate** (founder, 24 Nov 2026: three audits in a row found a new feature that spent past a limit or wasn't logged): Google Maps, Gemini and Venice are called only through `paidFetch`, which refuses outside `withCosts` (never logged) and past the person's limit (`LimitReached`; a route whose limit is its own, such as a friend's lookup, Admin's health check or Claude's scripts, says `limit: "route"`), and counts the call itself (a call cut off by its time limit at the flat price); lookups that answer "none" on failure answer "none" past the limit too; the eval fails on a paid address fetched anywhere else. Routes still check first, to say so nicely. Audit round 2 (24 Nov 2026): the same ask (a tweak, a typed search, an Ask Feta search) comes back from its kept set; Show me more on a kept list uses its stored backup first (`shown` from the phone); the late events ask checks only the events (`eventsOnly`); Saved looks up only places the phone doesn't already have (`x-feta-have`); an event venue's place ID is kept for everyone a month; an event search is claimed and an empty one kept an hour; her places Google can't find are tried again daily; Grounding with Google Maps is counted per prompt; a refused Google call isn't counted; Gemini at what each reply says it used (tokens, thinking and web searches, at Google's list price for the model that served it, `trackGemini`), and work that finishes after the reply (slow event searches, the day's Featured in search) with the request that started it (`later`) (founder, 21 Nov 2026: flat guesses logged ₹480 of a ₹2,100 Gemini day). Admin → Costs (founder, 23 Nov 2026, `components/AdminCosts.tsx`, `cost_monitor()`): every request to a route that can spend is one `api_hits` row (route, a hash of what was asked set with `askIs` inside the route's work, a label with no typed words, cost, services, time), so it shows per route the hits, spend, cost each and repeats (same person, same ask within 30 minutes) with what they cost, the asks repeated most, and spend per paid service. Backend audit, 24 Nov 2026: what a reply spent is logged at once and work finishing after it (guide posts, slow event searches) as its own rows when done (routes that start it run up to 300 s); a city's daily shared search is claimed by one search only (`claim_events_cache`); nothing more is spent past someone's limit (photos, live checks, a kept set is never checked twice); brand lookups count toward the person's own limit; admins are out of every count; people can't delete their own pick sets (that reset the search count). Test spend stays test spend: each cost row records whether it came from a test account when it's written (`api_costs.is_test`), so deleting a test account never turns its spend into real people's (24 Nov 2026). Anything paid that Claude runs outside the app (pictures, research, lookups from scripts) needs her OK with the price first and is logged with `scripts/log-spend.mjs` (route `script`, outside every daily pool); Admin → Costs shows this month's bills, everyone together, per service with Google Maps' free monthly calls taken off, and today's spend per bill (founder, 24 Nov 2026: "where has this money gone"). Test accounts (`?qa=<tester code>`) have their own pool and never use real people's (`TEST_USER_DAILY_BUDGET_INR`, `TEST_DAILY_BUDGET_INR`). Defaults for the testing phase (founder, 21 Nov 2026): ₹1,000 a person (real or test), ₹5,000 for all test accounts together. Searches left are counted from what this person's sets really cost today (a fresh set is about ₹100). What the limits say (`lib/limits.ts`): "Feta's in early testing, so picks are limited each day", never money; when 3 or fewer new searches are left, a message says how many; when none, "That's all for today" with See Saved; Style setup and Ask Feta say so before any questions; the reset (midnight India time) is said in their own time zone ("more from 6:30 pm"). A fresh set costs about ₹100 at list prices (searches, live checks of curated places and event venues, photos, Gemini); reused sets cost only live re-checks.

## Testing
- Test runs in a browser (AI QA, Claude) open Feta with `?qa=<tester code>` (`QA_CODE`) so they never count as people.
- `npm run journey` (founder, 18 Nov 2026): a browser walks through Feta as someone new (welcome, name, the questions with options ticked and typed, city, Home, You) on made-up places, ₹0, about 20 seconds, and checks every option is on screen, what they pick or type is saved and shows in You, and Home has picks. Must pass before pushing any change to screens or onboarding (`scripts/journey.ts`; it starts its own test server on port 3100, so stop any other `next dev` in this folder first). When a tester finds a screen bug, add a check for it.
- `npm run style-check` (founder, 20 Nov 2026): a browser goes through Style as someone who chose only Style, scrolls every Style screen to the bottom and checks Continue is on screen; needs a `FAKE_PLACES=1` dev server on port 3000. Must pass before pushing Style changes.
- `npm run db-check` (founder, 24 Nov 2026: three audits found database rules that only failed on the real database, like the share check that stopped WhatsApp sharing): a test account (tester code) makes the writes the app makes on the real database (shares of every kind, a kept list, a visit, usual brands) and checks that what must be refused is; ₹0, the account deleted at the end. Must pass after every migration and before pushing any change to database rules; when a new screen writes to the database, add its write here.
- `npm run eval`: the quality check (must pass). Every rule on this page that can be tested with made-up data has a check there ("Core rules" and the personas); a new rule gets its check in the same commit (founder, 23 Nov 2026: "it doesn't remember the core logic").
- `npm run live-check` (founder, 23 Nov 2026): three people on real Google data (Bengaluru vegetarian things to do, Lisbon vegetarian food, London Thai and Korean) and one Ask Feta chat, against a `next dev -p 3400` server without FAKE_PLACES; test accounts deleted at the end; about ₹100–250, so only with her OK, before a push that changes picks. `FAKE_PLACES=1` dev server: made-up places that look like a real city (`lib/server/fake-places.ts`), fake ranking, no events or photos, ₹0. Chat still calls Venice (a few paise).
- Live Google only when the change depends on real data: one short run, with her OK, and delete test accounts after.
